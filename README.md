# 校园报修工单智能分诊与派单智能体
> 杭州电子科技大学 第二届AIGC应用创新大赛 参赛作品 · 赛题二：AI智能体·业务流程自动化
>
> 零成本、纯Python实现、可一键公网部署的校园后勤报修智能分诊原型，人工强制确认兜底，覆盖多模态识别、动态预约、异常分支、全流程学生反馈闭环。

## 一、项目背景与解决痛点
传统校园报修存在以下问题：
1. 学生口语化描述故障，后勤调度需要人工反复电话沟通确认类型、紧急度
2. 派单依赖人工经验，容易出现技能不匹配、紧急工单排队延误
3. 学生提交后无明确反馈、无临时处理方案，只能被动等待
4. 备件不足、无空闲维修人员等异常场景无标准化处理流程

本智能体作为调度员辅助工具，**仅输出分诊建议，不自动派单**，所有工单必须经过人工确认后归档，兼顾AI效率与人工兜底。

## 二、核心功能
### 学生侧
- ✅ 文字+故障照片多模态提交，支持口语化描述
- ✅ 7天内动态预约：自动区分工作日/周末时段，过滤当日已过期时间，支持特殊时间备注
- ✅ 提交后立刻返回报修回执、预工单号、明确响应时效
- ✅ 分故障类型的临时自助排查方案，小问题可自行处置
- ✅ 工单号全流程进度查询，派单后可查看维修人员、联系电话、上门时间
- ✅ 后置人工升级通道：仅对AI结果有异议时可申请加急/复核，不默认展示

### 智能体分诊侧
- ✅ 基于规则知识库+关键词权重的故障分类，覆盖6大类校园常见故障
- ✅ 三级紧急度（P0/P1/P2）硬规则判定，安全风险自动触发最高级
- ✅ 置信度阈值0.7，低置信度自动追问，最多2轮，仍不明确直接转人工
- ✅ 自动匹配维修人员技能、当前排班负载、备件库存
- ✅ 覆盖两类异常分支：备件不足、无空闲维修人员，自动提示人工调度

### 调度员侧
- ✅ 强制人工确认节点，可调整紧急度、修改派单人员、录入沟通记录
- ✅ 自动生成标准化工单台账，支持JSON/CSV导出
- ✅ 完整保留AI判断依据、人工调整记录、升级申请原因

## 三、性能指标
- 50条批量测试用例分诊准确率：**94.9%**，满足项目要求≥90%的指标
- 核心场景测试通过率：100%（正常工单、信息缺失追问、高风险硬规则、备件不足、无空闲人员）
- 无外部大模型依赖，纯规则逻辑可解释，无API调用成本

## 五、本地运行（3步启动）
1. 安装依赖
```bash
pip install -r requirements.txt
```
2. 启动服务
```bash
streamlit run app.py
```
3. 浏览器自动打开页面，本地地址：`http://localhost:8501`，同局域网设备可通过Network URL访问。

## 六、公网一键部署（零成本，所有人可访问）
本项目原生支持Streamlit Community Cloud官方免费部署，无需购买服务器、无需内网穿透，步骤见部署指引：
1. Fork本仓库到自己的GitHub账号
2. 登录Streamlit Community Cloud，选择仓库、主文件`app.py`
3. 点击Deploy，等待2分钟即可得到公网可访问链接，全球任意网络可打开。

> 原型说明：免费版云端文件存储为临时存储，服务重启后测试工单会清空，不影响功能演示；生产环境可对接数据库持久化。

## 七、标准演示场景
1. 正常P0紧急工单：漏水/漏电描述，自动识别高风险，匹配对应技能维修人员
2. 信息缺失追问：仅描述“东西坏了”，自动追问位置、故障现象
3. 人工升级异议：学生不认可AI分级，在结果页提交升级申请，调度员可见
4. 备件不足异常：所需备件库存为0，自动提示人工跟进备件、协调时间
5. 无空闲人员异常：对应技能师傅负载已满，自动提示手动调度

## 八、设计原则
1. **人工兜底优先**：AI仅做建议，所有派单必须人工确认，不做全自动无人工闭环
2. **可解释性**：所有分诊结果基于公开知识库规则，无黑盒判断
3. **零成本**：无付费API、无服务器费用，学生可直接复现
4. **合规性**：仅使用模拟数据，不接入真实后勤系统、不收集真实隐私信息
